# Pholio implementation audit for the public legal rewrite

Reviewed September 15, 2026. Application source: `pholio-app` at commit `4200f91c3015a38ae7c89b83e5729dea74a8a4f3` (`implement pre-launch audits consent gates and webhook`). The working tree was clean when reconfirmed. This is a read-only implementation audit; it does not change application behavior or certify a deployed environment.

## Scope and method

Read the application repository's operating instructions, then traced current router registration, services, data transfer objects, migrations, browser components, and scheduled functions. Current executable paths take precedence over old architecture descriptions, comments, migration names, and dormant tables. In particular, the root app instructions still describe roster/commission functionality that is not all active, the data inventory calls Intel records historical although the current capture functions still write them, and several minor-related messages survive behind an adults-only launch gate.

No production database, environment secrets, vendor account, deployment configuration, contract, email inbox, billing dashboard, or service operation was accessed. “Implemented” below means there is a current executable path in this source checkout. It does not establish that its migration ran, credentials are configured, a scheduled job actually runs, an operator monitors it, a processor agreement exists, or a promised deadline is met. No end-to-end production transactions or test suite were run for this read-only audit.

The strategic/product-plan review is a separate input to the legal architecture. Missing implementation is a launch work item where an intended capability is part of the final approved product; it is not a reason to silently omit that capability from the legal scope. Conversely, a surviving schema table is not evidence that Pholio offers the corresponding service.

## Findings that materially affect the rewrite

1. **The current implementation has an adults-only launch policy.** Under-18 talent cannot publish, enter generic discovery, collect sensitive measurements, start ordinary new account workflows, or obtain new guardian authorizations. The older legal changelog still describes a 13+ minimum and guardian-supported minors. The final product decision must resolve this discrepancy. A dormant mailbox-consent system must not be described as complete guardian verification.
2. **Pholio serves several different relationships.** A talent owns a profile and chooses disclosures; a named agency receives a representation application; an event organizer receives an event-specific package; designers can use tokenized pick lists without accounts; an agency can export information to its own systems; and a researched off-Pholio destination may have no agreement or account with Pholio. A single statement that “agencies are our processors” or that every destination is a Pholio customer would be inaccurate.
3. **Account deletion is real, but incomplete across providers and data generations.** R2/local media and Firebase deletion have durable recovery. The deletion service does not cancel a Stripe subscription, request Stripe Identity redaction, or revoke a Phyllo connection. New identity-backed open-call data is not comprehensively covered by the talent-account inventory. Do not promise immediate, universal deletion or that closing an account itself cancels billing.
4. **Optional visitor analytics are only partly consent-gated.** Persistent visitor/session cookies and the legacy analytics table's IP/user-agent fields are gated. Another active capture path sends IP to a geolocation provider and records referrer/market/events without that gate. Declining analytics does not currently mean no audience analytics or no geolocation transmission.
5. **Creator-metric verification is not production-ready in the inspected implementation.** The Phyllo route is always mounted, its provider endpoint is a sandbox endpoint, missing credentials fabricate metrics, and the frontend can fall back to a mock. These metrics must not be presented as trustworthy verification to real agencies.
6. **Search processes legally sensitive distinctions.** Current discovery exposes user-selected heritage labels and evaluates those labels when an agency brief asks for them; gender can exclude a candidate. Separate optional image-analysis and embedding controls exist, but they do not by themselves authorize ethnic-origin disclosure or make every casting criterion lawful.
7. **Moderation infrastructure does not establish a staffed legal response program.** There is an authenticated report API, moderator queue, image screening, account suspension, and a CSAM escalation record. Those mechanisms do not establish a public notice-and-action intake, designated copyright agent, statutory removal response, preservation/reporting operation, appeals procedure, or trained coverage.
8. **Publishing a legal revision is a cross-repository change.** The app compares acceptance against a single version and requires a matching change summary. Updating only the public text creates a mismatch between what users accepted and what is served. The existing record overwrites the latest acceptance fields rather than keeping a complete immutable agreement history.

## Minors, adult context and identity verification

The current server policy requires a valid, plausible DOB indicating at least 18 for public exposure and sensitive measurements. Guardian consent is expressly not an exception during the adults-only launch. The global mutation gate blocks known minors while preserving narrow safety exits such as deletion, export, withdrawal, revocation and reports. Ordinary read-only self-management remains possible. A missing DOB is not treated as a minor by that global mutation helper, so protection also depends on route-specific validity/adulthood checks. [Age policy](/Users/lenquanhone/Projects/pholio-app/src/shared/lib/talent-age.js:98), [public exposure](/Users/lenquanhone/Projects/pholio-app/src/shared/lib/talent-age.js:145), [global gate](/Users/lenquanhone/Projects/pholio-app/src/shared/middleware/launch-age-policy.js:6).

Anonymous open-call intake relies on an adult-authority affirmation and its intake spec; it is not Stripe Identity verification. Its destination resolver deliberately leaves a matching existing minor profile unattached and creates an identity-only submission, while the consent snapshot selects the adult branch. The global logged-in age gate does not establish age eligibility for an anonymous applicant. Review these paths together before claiming the adults-only restriction is comprehensive. [Anonymous consent](/Users/lenquanhone/Projects/pholio-app/src/domains/opencall/services/submissions.js:940), [minor destination branch](/Users/lenquanhone/Projects/pholio-app/src/domains/opencall/services/submissions.js:880).

The guardian service underneath the launch prohibition uses hashed email-link tokens, a read-only preview followed by affirmative POST, account and named-agency scopes, independent grants, expiry/revocation and access-redaction machinery. It verifies access to a mailbox; it does not itself prove identity, adult age, parenthood or legal custody. Its own implementation notes identify missing consent-version/scope-text/evidence fields and the account-level field's collapse of several distinct permissions. New requests and confirmations are blocked at the router. [Guardian route prohibition](/Users/lenquanhone/Projects/pholio-app/src/domains/talent/routes/guardian-consent.js:38), [evidence limitation](/Users/lenquanhone/Projects/pholio-app/src/domains/talent/services/guardian-consent.js:278), [combined account scope](/Users/lenquanhone/Projects/pholio-app/src/domains/talent/services/guardian-consent.js:394).

If the final launch includes minors, work is required before making that representation publicly: reliable age/guardian eligibility, evidence of authority and informed consent, distinct publication/measurement/named-recipient permissions, age-up handling, safety and contact restrictions, withdrawal consequences, data minimization, rights handling and any child-performer/employment requirements. A work-permit checkbox or stored permit field is not a verified permit, trust account, school-hours policy or workplace-safety process. Preserve the adult gate until the intended minor program is actually ready; public copy alone cannot turn it on.

Stripe Identity is a separate, real optional flow for verified-adult context. It requests document verification with a matching selfie, compares returned DOB with the profile and verifies age ≥18. The application persists the Stripe session identifier, status, consent version/time, age/DOB-match results and timestamps; it does not persist the ID image/selfie or full returned DOB in that verification table. Raw documents/selfie are processed by Stripe, and the app transiently receives verified outputs. [Session creation](/Users/lenquanhone/Projects/pholio-app/src/domains/talent/services/age-verification.js:148), [verified-result handling](/Users/lenquanhone/Projects/pholio-app/src/domains/talent/services/age-verification.js:242).

After a verified Stripe session, the app awaits a redaction request and records success; failure is logged and left retryable. No durable retry queue for Identity redaction was found, and unsuccessful/abandoned verifications do not take that verified-session branch. Account deletion does not invoke it. This is a material retention/deletion gap, not a reason to omit Identity from the notice. [Redaction path](/Users/lenquanhone/Projects/pholio-app/src/domains/talent/services/age-verification.js:265).

Verified-adult context stores optional boundaries such as swimwear, lingerie, implied/artistic nudity and an OnlyFans URL. Saving explicitly sets named-submission and confirmed-job sharing flags to false; it does not authorize disclosure. Do not imply that a verified-adult badge authorizes nudity, sexual activity, commercial use or disclosure of these preferences to agencies. [Adult-context storage](/Users/lenquanhone/Projects/pholio-app/src/domains/talent/services/age-verification.js:119).

## Analytics, cookies and service providers

### Analytics behavior that must be reconciled

The shared `pholio_consent` cookie has necessary/analytics choices, a version and timestamp, a one-year lifetime and shared `.pholio.studio` scope. [Consent contract](/Users/lenquanhone/Projects/pholio-app/src/shared/lib/consent.js:24). Portfolio visitor cookies are host-only: `pholio_visitor_id` lasts one year and `pholio_session_<profile>` lasts 30 minutes; no affirmative analytics choice means neither session creation nor those identifiers are set. [Visitor tracking](/Users/lenquanhone/Projects/pholio-app/src/routes/portfolio.js:103).

However, two other behaviors remain:

- Legacy `analytics` rows are written without consent with IP/user-agent null, but include the full referrer inside metadata. Calling them wholly anonymous without qualification would be too strong. [Legacy event write](/Users/lenquanhone/Projects/pholio-app/src/routes/portfolio.js:71).
- The active Intel capture path writes viewer class, session ID when supplied, image/action/dwell/share-token/source/referrer and an IP-derived market. It calls the market resolver without consulting the analytics cookie. Share-token open/reopen counters also update outside that gate. The public portfolio calls these exported functions. [Intel write](/Users/lenquanhone/Projects/pholio-app/src/domains/talent/services/intel/capture.js:139), [share-token counters](/Users/lenquanhone/Projects/pholio-app/src/domains/talent/services/intel/capture.js:88), [portfolio call](/Users/lenquanhone/Projects/pholio-app/src/routes/portfolio.js:475).

A notice cannot fix this. Decide which strictly limited measurements have a supported non-consent basis, remove identifiers and sensitive referrer/query data from that path, and gate optional location/audience analytics end to end. Test initial refusal, later withdrawal, existing session cookies, public portfolio events, share links, separate app/site origins and any future custom domains. Analytics windows shown to a user (7/90 days) are not a database deletion schedule.
